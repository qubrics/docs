Use the Ruby SDK when your application needs gems for the Sending, Mailbox, or Management API.

<Info>
  For API-key authentication, Sending clients accept a send-capable `smx_mbx_` key or owner-approved Sending-resource `smx_agent_` token. Mailbox clients accept
  `smx_mbx_` keys or scoped `smx_agent_` tokens. Management API-key clients require
  team-scoped `smx_root_` keys.
</Info>

## Requirements

- Ruby 3.1 or newer.
- An API key or [REST OAuth grant](/developer-tools/oauth) for the surface you are calling.

## Install

Install a gem for each surface you use. These examples use `qubrics-sending` 2.0.0, `qubrics-mailbox` 3.0.0 and `qubrics-management` 3.0.0.

<CodeGroup>

```bash Sending
gem install qubrics-sending --version 2.0.0
```

```bash Mailbox
gem install qubrics-mailbox --version 3.0.0
```

```bash Management
gem install qubrics-management --version 3.0.0
```

</CodeGroup>

Use the `Qubrics` namespace with these gem versions, and check [package names and imports](/developer-tools/sdks/versioning-support#package-names-and-imports) before changing an existing installation so your gem version and namespace stay together.

## OAuth access tokens

Set `access_token` to a bare token string or callable. Do not also set `api_key`.

```ruby
require 'qubrics/management'

client = Qubrics::Management::Client.new(
  access_token: -> { ENV.fetch('QUBRICS_ACCESS_TOKEN') }
)
```

The provider runs before each request. Your application owns secure token storage, expiry checks, and refresh coordination; see [OAuth for REST APIs](/developer-tools/oauth#refresh-and-disconnect). Sending, Mailbox and Management clients accept the same token option.

## Create a client

Require the surface gem you installed, then create its client.

<CodeGroup>

```ruby Sending
require 'qubrics/sending'

client = Qubrics::Sending::Client.new(
  api_key: ENV.fetch('QUBRICS_MAILBOX_API_KEY')
)
```

```ruby Mailbox
require 'qubrics/mailbox'

client = Qubrics::Mailbox::Client.new(
  api_key: ENV.fetch('QUBRICS_MAILBOX_API_KEY')
)
```

```ruby Management
require 'qubrics/management'

client = Qubrics::Management::Client.new(
  api_key: ENV.fetch('QUBRICS_ROOT_API_KEY')
)
```

</CodeGroup>

Surface gems expose `Qubrics::Sending::Client`, `Qubrics::Mailbox::Client`, and `Qubrics::Management::Client` directly.

## Choose a surface

| Surface | Gem | Client or helper | API key |
| --- | --- | --- | --- |
| Sending | `qubrics-sending` | `Qubrics::Sending::Client`, `client.emails` | `smx_mbx_` or owner-approved `smx_agent_` with `email.send` |
| Mailbox | `qubrics-mailbox` | `Qubrics::Mailbox::Client`, `client.mailbox_api` | `smx_mbx_` or scoped `smx_agent_` |
| Management | `qubrics-management` | `Qubrics::Management::Client`, `client.mailboxes` | `smx_root_` |

<Note>
  Durable `smx_agent_` tokens are mailbox-compatible and include `mailbox.read`
  and `email.receive`, not `email.send`. After owner acceptance and approval,
  exchange the durable token for a one-hour Sending-resource token before sending.
</Note>

Sending 2.0.0 defaults to `https://smtp.qubrics.com/api/v1`. Mailbox 3.0.0 and Management 3.0.0 default to `https://app.qubrics.com/api/v1`.

## Shared API behaviour

Surface clients validate API key prefixes, configure bearer auth, and map generated API errors.

The helper examples below use `qubrics-core` 2.0.0, installed with these surface gems.

### Pagination

List responses use cursor pagination with `pagination.has_more` and `pagination.next_cursor`. The core gem exports `Qubrics::Core.each_cursor()` and `Qubrics::Core::CursorPager` for cursor iteration when you wrap a page-fetching function.

### Retries and rate limits

Surface clients call `Qubrics::Core::Retry.configure()` by default. Retries apply to safe methods and retry-safe `POST` requests that include `Idempotency-Key`, then honour `Retry-After` and `X-RateLimit-Reset` response headers.

Pass `Qubrics::Core::RetryOptions` into a surface client to change attempts, delays, or jitter.

### Idempotency and ETags

Use core header helpers when a generated operation accepts custom headers.

```ruby
headers = Qubrics::Core::Headers.conditional(if_match: etag)
headers.merge!(Qubrics::Core::Headers.idempotency_key('order-123'))
```

Use `Idempotency-Key` for retry-safe mutating requests. Use `If-Match` and `If-None-Match` with single-resource endpoints that support ETags.

### Errors

API errors are mapped to `Qubrics::Core::ApiError`. The error includes status, code, retryability, request ID, param, nested errors, response body, and response headers when available.

Use the request ID when contacting support.
