Use the Rust SDK when your application needs clients for the Sending, Mailbox, or Management API.

<Info>
  For API-key authentication, Sending clients accept a send-capable `smx_mbx_` key or owner-approved Sending-resource `smx_agent_` token. Mailbox clients accept
  `smx_mbx_` keys or scoped `smx_agent_` tokens. Management API-key clients require
  team-scoped `smx_root_` keys.
</Info>

## Requirements

- Rust 1.82 requires a compatible application `Cargo.lock`. Use stable Rust for fresh installs.
- An API key or [REST OAuth grant](/developer-tools/oauth) for the surface you are calling.
- An async context for API calls.

## Install

The Rust SDK is one crate with three surface modules.

```bash
cargo add qubrics@1.0.0
```

## OAuth access tokens

Use `new_with_access_token` for a bare token or `new_with_token_provider` for an asynchronous provider.

```rust
use qubrics::mailbox::MailboxClient;

fn oauth_client() -> qubrics::Result<MailboxClient> {
    MailboxClient::new_with_token_provider(|| async {
        Ok(std::env::var("QUBRICS_ACCESS_TOKEN")
            .expect("QUBRICS_ACCESS_TOKEN is required"))
    })
}
```

The provider runs before each request. Your application owns secure token storage, expiry checks, and refresh coordination; see [OAuth for REST APIs](/developer-tools/oauth#refresh-and-disconnect). The same token option is available for Sending and Management clients.

## Create a client

Import the surface client from the `qubrics` crate.

<CodeGroup>

```rust Sending
use qubrics::sending::SendingClient;

fn sending_client() -> qubrics::Result<SendingClient> {
    SendingClient::new(
        std::env::var("QUBRICS_MAILBOX_API_KEY")
            .expect("QUBRICS_MAILBOX_API_KEY is required"),
    )
}
```

```rust Mailbox
use qubrics::mailbox::MailboxClient;

fn mailbox_client() -> qubrics::Result<MailboxClient> {
    MailboxClient::new(
        std::env::var("QUBRICS_MAILBOX_API_KEY")
            .expect("QUBRICS_MAILBOX_API_KEY is required"),
    )
}
```

```rust Management
use qubrics::management::ManagementClient;

fn management_client() -> qubrics::Result<ManagementClient> {
    ManagementClient::new(
        std::env::var("QUBRICS_ROOT_API_KEY")
            .expect("QUBRICS_ROOT_API_KEY is required"),
    )
}
```

</CodeGroup>

Call this async function from your application to send a message.

```rust
use qubrics::sending::{Address, EmailSendRequest, SendingClient};

pub async fn send_welcome() -> qubrics::Result<()> {
    let client = SendingClient::new(
        std::env::var("QUBRICS_MAILBOX_API_KEY")
            .expect("QUBRICS_MAILBOX_API_KEY is required"),
    )?;

    let response = client
        .send_email(&EmailSendRequest::new(
            Address::new("sender@example.com").with_name("Example App"),
            Address::new("user@example.com"),
            "Welcome to Qubrics",
            "<p>Hello from Rust.</p>",
        ))
        .await?;

    println!(
        "queued {} via {}",
        response.data.message_id,
        response.request_id()
    );
    Ok(())
}
```

## Choose a surface

| Surface | Module | Client or helper | API key |
| --- | --- | --- | --- |
| Sending | `qubrics::sending` | `SendingClient`, `qubrics::sending` | `smx_mbx_` or owner-approved `smx_agent_` with `email.send` |
| Mailbox | `qubrics::mailbox` | `MailboxClient`, `qubrics::mailbox` | `smx_mbx_` or scoped `smx_agent_` |
| Management | `qubrics::management` | `ManagementClient`, `qubrics::management` | `smx_root_` |

<Note>
  `sending`, `mailbox`, and `management` are modules inside the `qubrics` crate. They are not separate installable crates.
</Note>

Sending uses `https://smtp.qubrics.com/api/v1` by default. Mailbox and Management use `https://app.qubrics.com/api/v1`.

## Shared API behaviour

Surface clients validate API key prefixes, attach bearer auth, and return a response with data, metadata, and the HTTP status.

### Typed and raw JSON coverage

Sending has typed request and response models. Mailbox and Management expose typed surface clients with raw JSON helpers. Their operation helpers return JSON values rather than the typed Sending models.

### Pagination

Mailbox and Management list helpers return paginated data as JSON. Read `pagination.has_more` and `pagination.next_cursor` according to the relevant API reference. The crate does not currently provide a typed cursor iterator for these surfaces.

### Retries and rate limits

The crate sends each request once. When `qubrics::Error::Api` reports `retryable` as `true`, follow the API retry guidance before sending the request again.

### Idempotency and ETags

Use `RequestOptions` when an operation accepts optional header values.

```rust
use qubrics::core::RequestOptions;

let send_options = RequestOptions::new().idempotency_key("order-123");
let update_options = RequestOptions::new().if_match(etag);

let _ = (send_options, update_options);
```

Use `Idempotency-Key` for retry-safe mutating requests. Use `If-Match` and `If-None-Match` with single-resource endpoints that support ETags.

### Errors

SDK methods return `qubrics::Result<Response<T>>`. API failures map to `qubrics::Error::Api` with the status, machine-readable code, retryable flag, raw response body, and request ID when available.

```rust
use qubrics::sending::{EmailSendRequest, SendingClient};

pub async fn send_and_report(
    client: &SendingClient,
    request: &EmailSendRequest,
) -> qubrics::Result<()> {
    match client.send_email(request).await {
        Ok(response) => {
            println!("request id: {}", response.request_id());
            Ok(())
        }
        Err(qubrics::Error::Api(error)) => {
            eprintln!("{} {:?}", error.message, error.request_id);
            Err(qubrics::Error::Api(error))
        }
        Err(error) => Err(error),
    }
}
```

Keep the request ID when contacting support.
