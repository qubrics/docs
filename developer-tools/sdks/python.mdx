Use the Python SDK when your application needs Qubrics API clients with API-key validation, retry handling, cursor helpers, and typed API errors.

<Info>
  For API-key authentication, Sending clients accept a send-capable `smx_mbx_` key or owner-approved Sending-resource `smx_agent_` token. Mailbox clients accept
  `smx_mbx_` keys or scoped `smx_agent_` tokens. Management API-key clients require
  team-scoped `smx_root_` keys.
</Info>

## Requirements

- Python 3.10 or newer.
- An API key or [REST OAuth grant](/developer-tools/oauth) for the surface you are calling.

## Install

Install the package for each API surface your application uses. The examples below use Sending 2.0.0, Mailbox 3.0.0 and Management 3.0.0.

<CodeGroup>

```bash All surfaces
pip install qubrics-sdk==4.0.0
```

```bash Sending
pip install qubrics-sending==2.0.0
```

```bash Mailbox
pip install qubrics-mailbox==3.0.0
```

```bash Management
pip install qubrics-management==3.0.0
```

</CodeGroup>

Use the `qubrics` imports shown below. The final old-name distributions install their replacements without providing the old import paths. See [package names and imports](/developer-tools/sdks/versioning-support#package-names-and-imports).

## OAuth access tokens

Set `access_token` to a bare token string or callable. Do not also set `api_key`.

```python
import os
from qubrics.mailbox import create_mailbox_client

client = create_mailbox_client(
    access_token=lambda: os.environ["QUBRICS_ACCESS_TOKEN"],
)
```

The provider runs before each request. Your application owns secure token storage, expiry checks, and refresh coordination; see [OAuth for REST APIs](/developer-tools/oauth#refresh-and-disconnect). The same token option is available for Sending and Management clients.

The `langchain-sendmux` wrapper accepts the same `access_token` option in `SendmuxToolkit(...)`. To use all three tools, request `mailbox.read` and `email.send` and select one mailbox at consent; the tools do not supply a mailbox selector.

## Create a client

Import the factory from the surface package you installed.

<CodeGroup>

```python Sending
import os
from qubrics.sending import create_sending_client

client = create_sending_client(
    api_key=os.environ["QUBRICS_MAILBOX_API_KEY"],
)
```

```python Mailbox
import os
from qubrics.mailbox import create_mailbox_client

client = create_mailbox_client(
    api_key=os.environ["QUBRICS_MAILBOX_API_KEY"],
)
```

```python Management
import os
from qubrics.management import create_management_client

client = create_management_client(
    api_key=os.environ["QUBRICS_ROOT_API_KEY"],
)
```

</CodeGroup>

Surface packages expose `create_sending_client`, `create_mailbox_client`, and `create_management_client` directly.

## Choose a surface

| Surface | Package | Factory | API key |
| --- | --- | --- | --- |
| Sending | `qubrics-sending` | `create_sending_client` | `smx_mbx_` or owner-approved `smx_agent_` with `email.send` |
| Mailbox | `qubrics-mailbox` | `create_mailbox_client` | `smx_mbx_` or scoped `smx_agent_` |
| Management | `qubrics-management` | `create_management_client` | `smx_root_` |

<Note>
  Durable `smx_agent_` tokens are mailbox-compatible and include `mailbox.read`
  and `email.receive`, not `email.send`. After owner acceptance and approval,
  exchange the durable token for a one-hour Sending-resource token before sending.
</Note>

Sending uses `https://smtp.qubrics.com/api/v1` by default. Mailbox and Management use `https://app.qubrics.com/api/v1`.

## Shared API behaviour

The surface factories validate API key prefixes, attach bearer auth, and wrap generated API errors.

### Pagination

List responses use cursor pagination with `pagination.has_more` and `pagination.next_cursor`. The core package exports `iter_cursor_pages()` for cursor iteration when you wrap a page-fetching function.

### Retries and rate limits

Surface clients use a retrying request client. It retries safe methods and retry-safe `POST` requests that include `Idempotency-Key`, then honours `Retry-After` and `X-RateLimit-Reset` response headers.

Pass `RetryOptions` into a client factory to change attempts, delays, or sleep behaviour.

### Idempotency and ETags

Use core header helpers when a generated operation accepts custom headers.

```python
from qubrics.core import conditional_headers, idempotency_headers

headers = {
    **idempotency_headers("order-123"),
    **conditional_headers(if_match=etag),
}
```

Use `Idempotency-Key` for retry-safe mutating requests. Use `If-Match` and `If-None-Match` with single-resource endpoints that support ETags.

### Errors

Generated client exceptions are mapped to `QubricsApiError`. The error carries the API error code, retryability, request ID, status, headers, and raw body when available.

Use `error.retryable` and `error.request_id` when deciding whether to retry or contact support.
